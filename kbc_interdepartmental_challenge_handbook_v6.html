Page 01 · Common handbook

Rules, regulations & submission

These baseline rules apply across AI/ML, Web Development, UI/UX and Cybersecurity unless organisers publish a department-specific clarification.

Read before choosing a project

01 · Team & project scope

  • Choose exactly one problem statement per team.
  • Follow the team size and eligibility announced by your department organiser.
  • Assign a team lead and divide work clearly.
  • Do not switch problem statements after the announced lock date without approval.
  • Every team must be able to explain its own contribution.

02 · Originality & integrity

  • Do not copy another team’s code, UI, prompts, architecture, dataset preparation, evaluation or presentation.
  • Use tutorials/templates for learning or boilerplate only; implement and understand your solution.
  • AI assistants are allowed where permitted, but disclose significant tools/models and verify generated work.
  • Credit third-party assets, datasets, libraries and references.
  • Copied or misrepresented work may be disqualified.

03 · Minimum product quality

  • Build a working, demonstrable product—not only slides, mock data screenshots or a notebook where an application is required.
  • Implement the mandatory features and checkpoints listed under your selected statement.
  • Provide validation, useful error messages, loading/empty states where relevant and a usable interface.
  • Keep configuration and secrets out of source control.
  • Clearly label demo/sample data and simulated functionality.

04 · Data, privacy & safety

  • Use public, synthetic or organiser-approved data and respect its licence.
  • Do not expose personal, confidential, financial or college records without explicit permission.
  • Never publish API keys, passwords, tokens, private keys or credentials.
  • Cybersecurity testing must stay within your own lab or an explicitly authorised scope.
  • Do not deploy malware, steal credentials, disrupt services or run unauthorised scans.

05 · Required deliverables

  • Working hosted link or evaluator-accessible demo.
  • GitHub repository/source code with dependency and configuration instructions.
  • README explaining problem, approach, setup, architecture, limitations and test steps.
  • Short presentation/PPT and demo evidence (screenshots or video where requested).
  • Test evidence showing normal use and at least some failure/edge cases.
  • UI/UX teams must include the organised Figma file and interactive prototype link.

06 · Demo & evaluation

  • Be ready to explain design decisions, architecture, data sources, security and trade-offs.
  • Judges may test the working solution against the stated checkpoints.
  • Do not claim features are live if they are simulated or unfinished.
  • State known limitations and what you would improve next.
  • Web Development source brief requires GitHub repository link, PPT and deployed website link; shortlisted teams may be called for a pitch round.

AI · 01Intermediate–Advanced

College Knowledge RAG Assistant

Students lose time searching through notices, rules and timetables. Build a chatbot that answers questions only from approved college documents and always shows where each answer came from.

Compulsory features
  • Load at least 10 approved college documents, split them into chunks and create embeddings
  • Find the most relevant passages for each question and generate the answer from them
  • Show the document name and passage as a citation with every answer
  • Reply “insufficient evidence” when the documents do not support an answer
  • Web UI and backend/API with loading and error states
  • Test on at least 20 questions, including at least 5 that the documents cannot answer
Expected outcomeA working chatbot: the student asks a question and gets a short answer with citations, or a clear “insufficient evidence” message. A test report shows how many of the 20+ questions were answered correctly and how the unanswerable ones were handled.
AI · 02Intermediate–Advanced

AI Research Agent

Build an agent that takes a topic, researches it across several sources and writes a structured report in which every claim is linked to a source.

Compulsory features
  • Accept a research query and show the visible steps: plan → search → read → synthesize
  • Use at least 3 independent sources
  • Extract evidence from each source and write a structured summary
  • Link every claim to its source; no unsupported claims
  • Include an “insufficient evidence” fallback
  • Evaluate at least 10 queries for citation validity and factual support
Expected outcomeA research tool that produces a readable, sectioned report with working source links, plus an evaluation table for 10+ queries showing how many citations were valid and supported the claim.
AI · 03Intermediate–Advanced

AI Scam & Phishing Detector

Build a tool that checks a message or URL for scam or phishing signs and explains why, without ever claiming to be 100% certain.

Compulsory features
  • Accept message text, a URL, or both
  • Return one result: likely safe, needs review or likely scam, with a score and reasons
  • Point out indicators such as urgency wording and suspicious domains
  • API plus a usable web interface
  • Evaluate on held-out data using precision, recall and F1, with a false-positive/false-negative analysis
  • Use only anonymised or synthetic examples and show an uncertainty disclaimer
Expected outcomeA web app where a user pastes a message or link and gets a verdict, score and plain-language reasons. An evaluation report with precision, recall, F1 and examples of where the tool was wrong.
AI · 04Intermediate–Advanced

Multimodal Document Intelligence

Build a tool that reads invoices, receipts or forms (images or PDFs), pulls out the key fields and checks that the values make sense.

Compulsory features
  • Upload a document and preview it

  • Validate values, for example totals add up and dates are valid
  • Flag low-confidence or missing fields instead of guessing
  • Export results as CSV and JSON, and expose an API
  • Evaluate on at least 30 held-out documents and report field-level accuracy
Expected outcomeAn app where a user uploads a document, sees the extracted fields with confidence flags, and downloads CSV/JSON. An accuracy table shows how well each field was extracted across 30+ documents.

AI · 07Intermediate–Advanced

AI-Generated Media / Deepfake Detector

Build a tool that estimates whether an image may be AI-generated, shows how confident it is and is honest about its limits.

Compulsory features
  • Upload and preview an image (video is optional)
  • Run a trained or fine-tuned classifier, or another defensible detection pipeline
  • Show likely authentic, likely AI-generated or inconclusive, with a confidence value
  • Explain the signals used and state clearly that the result is an estimate, not proof
  • Evaluate on held-out samples, including images from generators not seen in training
  • Use only permitted public or consenting images; never accuse a person based on the output
Expected outcomeA web app that returns a verdict with confidence and an explanation. An evaluation report shows accuracy on unseen data and unseen generators, and lists the tool’s known weaknesses.
AI · 08Intermediate–Advanced

Cybersecurity Log Investigation Agent

Build an assistant that reads security logs, spots suspicious activity and gives a human analyst the evidence to decide what to do.

Compulsory features
  • Upload, parse and normalise synthetic or public logs
  • Detect at least 3 event types, such as brute-force attempts or suspicious scans
  • Show severity, indicators, evidence log lines and an explanation for each finding
  • Recommend actions only; no automatic blocking or counter-action
  • Backend/API and a web interface
  • Evaluate on labelled data, report false positives and anonymise identifiers
Expected outcomeA dashboard where an analyst uploads logs and sees ranked findings with the exact log lines behind each one. An evaluation report shows detection results and false positives.
